# 电量历史 1.0.0

开发者：阳影X（YangYingX）。电栖的独立可选插件，ID 为 `battery-history`。只使用宿主已有设备快照，不重复查询硬件、不联网，不进入主程序默认构建、安装包或便携包。

## 兼容与使用

稳定版宿主最低要求为 **电栖 1.0.8**，支持 API 1/2/3；本插件使用 **API 2** 的交互插件及异步保存接口。电栖 **1.0.7 不支持此插件**；不能仅把 DLL 放入 1.0.7 后使用。1.0.0 首次以独立 ZIP 附件随 [GitHub Release v1.0.8](https://github.com/YangYingX/Perivolt/releases/tag/v1.0.8) 公开发布，仍不随默认包安装。

在仓库根目录运行：

```powershell
.\scripts\Build-Plugin.ps1 -Project Extensions\Optional\BatteryHistory\BatteryHistory.csproj
```

独立 ZIP 解压到兼容宿主旁的 `plugins`，应形成 `plugins/battery-history/plugin.json` 与 `Perivolt.BatteryHistory.dll`，保留包内说明和许可文件。在插件页启用，再点击打开，显示单实例电量历史窗口。可选择设备、最近 24 小时或 7 天，查看 0–100% 百分比及本地采样时间。窗口跟随宿主主题；关闭窗口后，启用中的插件继续采样，停用插件会关闭窗口并停止采集。

界面当前以中文为主，尚未完成四语翻译；更长时间的实体设备与长期写入覆盖仍待继续验证。

## 采样边界

- **首次启用后才开始采样**，不回填启用前的读数。必须有已知且在线的连接状态、有效的 0–100 电量和前进的 `UpdatedAt`，时间还须位于本次扫描窗口内。重复时间戳、过期、未来、未知电量或离线读数不追加。
- 明确标为“缓存”或 `cache` 的来源不记录。Windows 电量属性可记录为**系统报告**，窗口会提示它可能受驱动缓存影响，不宣称设备实时上报；宿主为本次系统读取生成时间戳，插件无法判定设备内部实际报告时间。BLE 电池服务和厂商协议按宿主提供的新读数时间采样。
- 同一百分比最多每分钟采样一次，百分比或来源性质变化时记录；恢复连接会开始新线段。设备从快照中消失、明确离线/连接未知/读数失效后再恢复，以及样本间隔超过 5 分钟时不连线，不对空白区间插值或补点。
- 这些是电量百分比历史，不是功率、能耗统计或剩余使用时间预测。没有有效样本时显示原因提示，图表为空是正常状态。

## 本地保存与清理

宿主为插件提供独立数据目录，保存为 `history.json`。只保存设备 ID 的 SHA-256 摘要、清理过的显示名称，以及采样时间、百分比、断点和系统报告标志；不保存 MAC 地址、实例路径、硬件标识、诊断、原始报文或整个设备快照。名称中的已知原始标识及常见 MAC 格式会移除。名称是用户可见信息，仍可能包含用户自行设置的昵称。

最多保留 **7 天、16 台设备、每台 12,000 条样本**；到达上限时淘汰最旧样本或最久无记录的设备。JSON 读取上限 32 MiB，异常文件不自动覆盖，错误在窗口底部显示；需要时先备份原文件，再使用“清空本地历史”重新开始。清空会删除全部设备在界面和本地文件中的历史内容，不影响宿主设备设置。

普通保存每 30 秒批量进行，使用容量 1 的队列和一个后台文件工作器，临时文件完整写入后再原子替换。空的 `history.lock` 只协调同一数据目录的写入，不含设备资料；后启用的实例会等待旧实例完成最后保存并释放独占锁，再加载历史，避免旧尾批次覆盖新数据。等待超过 10 秒会在窗口报错，需停用后重新启用，不会绕过锁写入。

正常退出时，兼容宿主会在有限时间内异步等待当前批次落盘；停用插件会停止采样并让已排队的最后批次后台收尾，不长时间阻塞界面。退出等待超时、强制结束进程或断电时，最近尚未写入的批次仍可能丢失。错误不会抛到扫描回调中；磁盘不可写时曲线可暂存于内存，窗口显示保存失败。
