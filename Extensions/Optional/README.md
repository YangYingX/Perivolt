# 可选插件开发约定

此目录用于存放电栖后续增强插件源码；[插件总目录](../README.md)列出已实现与待开发项目。当前只有开发约定，尚无任务栏增强或用电趋势的实现。

## 范围

| 计划插件 | 功能范围 | 宿主需要提供的能力 |
| --- | --- | --- |
| 任务栏增强 | 悬停多设备概览、滚轮切换设备、读数状态说明；后续可增加多显示器增强 | 任务栏交互及显示挂钩；需要时再添加最小契约 |
| 用电趋势 | 本地电量百分比历史、变化趋势与查询界面 | 已有 `OnScan` 可接收设备快照；历史存储与展示由插件负责 |

API v1 当前支持设备读取、提醒和主题，**尚未提供任务栏 UI 扩展接口**。不要通过反射、注入、全局输入钩子或修改内部窗口来绕过契约；开发首个具体功能时，再为宿主增加必要的接口和兼容性检查。主程序保持现有任务栏基础显示，增强逻辑、界面、历史采集与存储放在可选插件中。设备快照通常只有电量百分比或档位，不能据此宣称精确功率、能耗或剩余使用时长。

## 开发与分发

1. 一个插件一个子目录，包含项目、`plugin.json` 和说明；稳定保留插件 ID，注明宿主最低版本和 API 版本。
2. 复用宿主已有设备扫描结果，不重复轮询硬件。未安装不产生开销，未启用不加载 DLL；停用或退出时通过 `Dispose()` 释放插件创建的订阅、定时器和资源。宿主等待在用回调结束后异步清理，不会强行中断。`OnScan` 和 `Dispose()` 均在后台执行；开发界面插件时须同时补充 UI 线程调度与清理契约，不能直接在回调中操作 WPF 控件。
3. 界面隐藏时停止动画；历史采集只在插件开启后运行，本地保存，设置有限的保留范围。数据未知或过期时如实显示，不将缓存值冒充实时电量。
4. 独立编译和打包，不加入 `Essentials`、`VendorProtocols` 或默认构建白名单。使用仓库根目录的 `scripts/Build-Plugin.ps1 -Project <项目路径>` 生成独立分发包。
5. 完成后在[插件总目录](../README.md)登记使用说明与下载入口；随插件发布许可、署名和第三方声明，不附带主程序、运行时或用户个人数据。

宿主和插件版本可独立发布。尚未实现或未经验证的能力保持标注为“待开发”，不提供空壳清单让用户误以为已经可用。
