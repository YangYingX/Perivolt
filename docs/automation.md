# 外设自动化中心

适用于 Windows **1.1.0** 正式版，下载见 [1.1.0 发行页](https://github.com/YangYingX/Perivolt/releases/tag/v1.1.0)。侧栏和托盘的“外设自动化”均可进入；桌面场景、自由卡片及充电提醒仍可独立使用。macOS 版仍在开发中，本页描述 Windows 版功能。

## 创建第一条规则

1. 先在“设置 → 桌面卡片”保存需要的场景，例如“工作”和“游戏”；需要音频联动时，先连接输出设备。
2. 打开“自动化”，新建规则或从耳机、游戏、夜间模板开始。模板只是草稿，须选择真实设备、场景或进程后保存。
3. 选择触发事件，按需添加条件，选择“满足全部条件”或“满足任一条件”。不添加条件时直接响应触发事件。
4. 按执行顺序添加动作，可上下移动。点击“检查规则”查看当前条件和动作；检查不会修改系统设置，也不消耗冷却。
5. 保存并启用规则，再开启页面右上方的“启用自动化”。总开关默认暂停；开启后的首轮采样建立基线，不会把当前已连接的设备或已运行的应用当成刚发生的事件。

每台设备使用已有稳定标识选择，不靠同名匹配。已经记录但暂时离线的设备也可作为触发目标。音频输出选择当前可用的 Windows 端点；列表变化后可点击“刷新音频输出”。

## 触发与条件

| 触发事件 | 含义 |
| --- | --- |
| 设备连接／断开 | 后续成功扫描确认连接变化；首次及失败恢复后的首轮只建立基线。未知连接不会制造重连。 |
| 电量降至阈值 | 新的有效百分比从阈值以上降至阈值或以下，且未明确报告正在充电。旧读数、缓存值和未知电量不触发。 |
| 开始／停止充电 | 新鲜读数确认充电状态变化；未知充电状态不会被当成停止充电。 |
| 应用启动／退出 | 指定进程名从没有实例变为至少一个实例，或最后一个实例退出。填写 `game.exe` 一类进程名，不填写路径。 |
| 每日时间 | 到达本地 `HH:mm`，每天最多触发一次；不补执行休眠、关闭或暂停期间错过的时间。 |

附加条件可检查设备在线／离线、电量不高于阈值、明确充电／未充电、应用运行／未运行，以及时间段。时间段包含起始时刻、不包含结束时刻，可跨午夜，例如 `22:00–07:00`。未知状态不会作为“未充电”等反向条件的证据。

设备变化的响应速度取决于现有电量扫描间隔，不会为规则额外查询外设。应用与时间约每两秒采样，只查询已启用规则引用的进程名，不读取窗口标题、内容或应用文件；采样间隙内启动又退出的短进程可能无法检测。

## 顺序动作

| 动作 | 行为 |
| --- | --- |
| 应用桌面场景 | 恢复所选场景中的主题、卡片布局、显示设备和位置。 |
| 切换音频输出 | 选择 Windows 默认输出；固定使用特定设备的应用仍由其自身设置决定。 |
| 输出音量／输出静音 | 修改执行时默认输出的音量或静音。可先切换输出，再设置其音量。 |
| 通信麦克风静音 | 修改 Windows 默认通信麦克风的端点静音，不录音，也不代表软件内或物理麦克风开关。 |
| 全局提醒开关 | 开启或暂停普通充电提醒及遵循该开关的登场卡。 |
| 显示通知 | 显示规则填写的通知；普通提醒关闭时跳过此动作。 |
| 恢复之前配置 | 选择拥有恢复点的规则，恢复它执行前的配置；“本规则”使用本规则已有的恢复点。 |

动作从上到下串行执行。某一步失败会停止后续动作，已完成的修改保留，结果和原因写入执行记录。可通过恢复入口处理已经完成的修改。保存规则时会检查目标场景、规则和音频端点；设备在执行期间断开时仍可能导致动作失败。

默认输出切换沿用现有 Windows 音频实现，其中默认设备设置依赖未公开的系统 COM 接口。程序会核验结果并报告失败，但不能保证所有 Windows 版本或驱动组合均支持；无法操作时可通过系统声音设置完成。

## 恢复与暂停

“设备连接”和“应用启动”规则可勾选“结束后自动恢复”。对应设备确认断开或指定应用全部退出后，会处理本规则的恢复点，不必另建一条退出规则。也可以建立“应用退出”规则，并添加“恢复之前配置”动作，选择对应的应用启动规则。

恢复只处理规则实际改过的设置。手动或其他操作已经改过的值会保留，并在记录中说明；音频端点离线、状态不完整或写入失败时，可能只能部分恢复，可在设备恢复可用后手动重试。失败恢复点不会因切换主题等普通设置变更而自动重试。后续规则仍使用相同设置时，较早规则的恢复会排队，待后续规则释放后继续处理。

总暂停会停止新的规则动作；已执行的修改仍保留，单条恢复和“恢复全部配置”仍可使用。重新开启时重建基线，不重放暂停期间的连接、启动或时间事件；已有结束恢复点在确认对应设备或应用结束后仍可进入恢复流程。删除或停用规则时，也会尝试处理其已有恢复点。

恢复点只保存在本次程序运行的内存中。正常退出会在有限时间内尝试恢复并保存记录；强制结束、关机或恢复失败不能保证全部还原。请通过执行记录和系统设置确认结果。

## 两个配置示例

**耳机连接后进入游戏场景**：选择“设备连接”，指定耳机，勾选结束后恢复；依次添加“切换音频输出 → 设置输出音量 → 应用桌面场景”。耳机确认断开后，尝试切回原输出、音量及桌面场景。

**游戏启动后暂停普通提醒**：选择“应用启动”，填写真实游戏进程名，勾选结束后恢复；依次添加“应用桌面场景 → 设置全局提醒（关闭）”。游戏全部退出后，尝试恢复原场景和提醒开关。可添加 `22:00–07:00` 时间条件，让规则只在夜间启动时生效。

## 记录、保存与限制

- 最多保存 32 条规则；每条最多 8 个附加条件、12 个动作，冷却为 0–86400 秒。规则和总开关随原设置保存。
- 执行历史写入数据目录的 `automation-history.json`，最多保留最近 200 条，可展开查看每一步或清空记录。写入失败会显示提示；清空记录不会撤销系统修改或删除规则。
- 手动执行仍检查条件、启停状态和冷却。检查规则只预览，不修改系统状态。
- 自动化不新增联网功能，不添加全局键鼠钩子，不读取麦克风音频流。
- 已验证规则、条件与恢复流程；音频恢复使用模拟状态验证，系统音频接口仅做读取检查。真实音频写入、不同音频驱动、真实多屏混合 DPI 拖动和实体设备连接抖动仍需进一步实机验证。
