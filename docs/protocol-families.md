# 按协议族适配外设

开发记录：2026-10-20，面向下一版本，未包含在已发布的 1.0.1 中。

适配单位是共用的设备协议，不是每个型号各写一个读取器。硬件表负责识别同族设备，解析器复用同一套请求、响应与状态规则。型号反馈用于验证固件和硬件修订，不作为开始开发的前提。同一品牌可能采用不同芯片及报文，不能仅凭品牌名称发送指令。

本次新增六个协议族，覆盖迈从、狼途、赛睿、海盗船、HyperX 五家厂商，放在默认开启且可关闭的 `vendor-protocols` 插件中。应用离线读取，不安装厂商软件、不联网获取协议、不注入进程、不更改设备配置。

## 迈从耳机

| 协议族 | 官方设备表 / 公开硬件记录对应的范围 | USB 标识 |
| --- | --- | --- |
| 旧版耳机电量查询 | S9 Pro、G9 Pro、V9 Pro | `291D:385D` |
| 同一旧版查询 | X9、V9 Turbo | 分别为 `3837:6045`、`3837:6008` |
| 新版带长度及校验字段的查询 | V9 Pro 2、R9 | 分别为 `3837:6011`、`3837:6013` |

匹配厂商集合、64 字节输入/输出长度，并从 HID 描述符核实两方向都声明 Report `55`、63 字节有效载荷。`291D:385D` 另外限制在已公开实测的 `FF90/0001` 集合。其他 USB 标识、音箱、有线固件接口、普通键鼠输入均不发送查询。

- 旧版 Windows 请求：`55 65 01` 后补零至 64 字节。响应有效载荷为 `65 <百分比> <状态>`，状态 `02` 放电、`03` 充电、`04` 已满、`1A` 休眠。
- 新版 Windows 请求：`55 AA 01 00 01 00 01 0B` 后补零。只接受版本 1、响应类型 `00 01`、命令 `0B`、长度 3；有效数据为唤醒状态与电量标志。电量低 7 位为百分比，高位为充电。启用校验时核对 XOR，关闭校验时仍核对零校验字节。
- 休眠时清除电量与充电状态。未响应、未知状态或不合格报文不会变成 0%。不按已满状态强行把读数改为 100%。

官方驱动对部分旧版耳机还有固件门槛。PowerHub 不更新固件，也不切换工作模式；不支持查询的固件将保持未知。这些型号范围不包含所有同名产品的硬件修订。

## 狼途 Shinetek 键盘系列

官方多设备驱动把 L102、L99、T75、T98、LT84 PRO 放在同一协议 1 下，共用 `1A2C:8FFF` 无线接收器与 `FF02/0002` 厂商集合。PowerHub 复用一个解析器：

| 键盘 | 本体 / 响应中的硬件标识 |
| --- | --- |
| L102 | `1A2C:A116` |
| L99 | `1A2C:B002`、`1A2C:B807` |
| T75 | `1A2C:A071` |
| T98 | `1A2C:A047` |
| LT84 PRO | `1A2C:A137` |

接受 32 或 64 字节有效载荷，由 HID 描述符读取真实的输入、输出 Report ID。状态请求为 `AA 55 CC 33 0E` 后补零，响应中检查相同头部与命令，百分比在有效载荷第 5 字节，模式在第 6 字节，充电标志在第 7 字节，实际 VID/PID 在第 8–11 字节（大端序）。字节下标从 0 开始。

响应必须报告已知的实际键盘 VID/PID，不能只凭通用接收器 ID 判定兼容。无线模式 `01` 才让接收器对应的键盘上线，有线模式 `03` 只让本体上线；状态 `00` 或切换至其他连接模式时清除该接口的电量。未知模式拒绝采用，未知充电标志保持未知。官方界面将 95% 以上显示为 100%，PowerHub 保留设备报告的原始有效百分比。

`1A2C:B006` 是官方页面特殊处理的有线 L102 接口，页面直接设为 100%，缺少真实电池证据，**不纳入电量读取**。T87/T88、F99/LT75/LT95 等来自其他驱动平台，不能据此宣称全部兼容；后续按各自共享平台调查，而不是向它们发送本协议试探。

## 赛睿 Nova 7 系列

VID `1038`，厂商集合 `FFC0/0001`，仅接口 MI 03。共用只读状态请求 `00 B0`，同时接受 Windows 无编号输入前缀 `00` 与直接 `B0` 报告。检查 HID 描述符确实声明对应报告后才查询。

| 电量编码 | PID |
| --- | --- |
| 原生 0–4 档位 | `2202`、`2206`、`220A`、`223A`、`227A`、`22A4` |
| 原生百分比 | `22A1`、`227E`、`2258`、`229E`、`22AD`、`22A9`、`22A5`、`22A7`、`2298` |

包括 Nova 7 / 7P / 7X、对应 Gen 2、2026 更新及相应限定版的上述硬件身份。响应 `B0` 的第 1 字节为连接状态，`03` 才视为在线；第 2 字节为电量，第 3 字节为充电标志。原生档位显示为“档位 n/4”，0–1 档标记低电，不换算为虚假的精确百分比。超过编码范围或未知状态的报文被拒绝。

这些字段采用 Linux 已合入的 Nova 状态协议，并与 HeadsetControl 的设备表交叉核对；后者的旧版仅按充电字节判断在线，PowerHub 采用独立的连接状态字段。Nova 5 在公开实现中的布局存在差异，本轮不将 Nova 7 的布局直接套用到 Nova 5、Nova Pro、Elite、GameBuds 或赛睿鼠标。

## 海盗船 VOID / 关联旧版耳机协议

VID `1B1C`，集合 `FFC5/0001`，MI 03。PID：`1B1C`、`1B27`、`0A14`、`0A16`、`0A17`、`0A1D`、`0A1A`、`1B2A`、`1B23`、`1B29`、`0A55`、`0A51`、`0A52`、`0A38`、`0A4F`、`0A2B`、`0A75`、`0A56`。

只发送 `C9 64` 电量查询，不使用软件控制模式或唤醒握手。检查响应 `64 00 <电量及麦克风标志> B1 <状态>`，电量去除最高位的麦克风标志后必须在 0–100。状态 `00` 为断开，`01` 正常，`02` 低电，`04/05` 充电。没有该厂商集合或对应报告的接口不查询。列出的 USB 身份可能涉及不同连接方式，不能据此推断有线供电等于充电。

需要不同路由协议或唤醒步骤的 VOID V2 / HS80 Max / Virtuoso 系列不使用本读取器。

## HyperX Cloud 共享 66 协议

VID `03F0`，集合 `FF13/0001`。PID `05B7`、`0C9D` 对应 Cloud III Wireless；`069F`、`0995` 对应公开实现列出的 Cloud II Core Wireless 身份。输入输出长度限制在 62–65 字节，并核对描述符声明 Report `66`。

先发送 `66 82` 查询无线连接，仅在回复确认在线后发送 `66 89` 查询电量，再用 `66 8A` 查询充电。分别接受命令回显与响应命令 `0B/0D/0C`；电量响应的状态字段必须非零，百分比须在 0–100。充电状态仅接受未充电、充电、已满三个值；读不到充电状态时可保留本轮已确认的电量，但充电显示未知。

只实现已确认的 Output/Input 查询路径。部分 Windows 固件需要 Feature 报告通道，暂未加入该兼容路径。Cloud II Wireless、Cloud III S、Alpha 等其他协议不套用这套命令。网上另有 `0795` 线索，与本轮上游设备表不同，尚不纳入。

## 读取成本与防误匹配

读取器不新增常驻线程或定时器，沿用现有扫描周期和最多四个查询槽。迈从、狼途、赛睿、海盗船每轮各发送一次状态请求；HyperX 依次查询在线、电量和充电。每个接口总 I/O 等待上限 600 ms，每个响应最多检查 12 个输入包，共享打开厂商接口，退出时关闭句柄并取消超时令牌；描述符未声明预期报告时不发送查询。

不会进行配对、灯光、DPI、按键、音效、固件、工作模式写入。报告回显、错误命令、错误长度、超范围百分比、错误校验、其他厂商或未知键盘身份均不能成为有效电量。普通键鼠输入集合不参与这次扩展。

## 验证边界

本轮主程序与插件编译通过，266 项临时断言覆盖族匹配、请求格式、零电量、满电、充电、原生档位、睡眠、截断及错误报文、回显、校验、未知设备、描述符歧义、已编译插件路由和系统缓存不能覆盖协议离线状态。应用自检通过。临时测试源文件及生成目录在使用后删除。

当前没有上述新增厂商设备可供 PowerHub 实机查询。新增项属于**协议实现完成、待实体设备验证**；不据此承诺全部固件可用。下一步实体测试应覆盖开关机、休眠唤醒、拔插、充电和无线/有线切换，并与官方驱动的读数比对。
